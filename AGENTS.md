# Repository Guidelines

## Project Structure & Module Organization

This React single-page app uses Vite and TypeScript. Startup is in `src/main.tsx`; global styles and Tailwind setup are in `src/index.css`. Add file-based routes under `src/routes/` (for example, `src/routes/projects.tsx` maps to `/projects`). Shared UI primitives belong in `src/components/ui/`, shared components in `src/components/`, and helpers in `src/lib/`. Static files go in `public/`; bundled assets belong in `src/assets/`. Product specifications live in `docs/`.

`src/routeTree.gen.ts` is generated by the TanStack Router tooling. Do not edit it by hand; let the development or build tooling regenerate it when routes change.

## Build, Test, and Development Commands

- `npm install` installs dependencies from `package-lock.json`.
- `npm run dev` starts the Vite development server with route generation.
- `npm run build` runs TypeScript project checks and creates the production bundle in `dist/`.
- `npm run preview` serves the production bundle locally for inspection.
- `npm run lint` runs ESLint across the repository.
- `npm run test` runs the Vitest suite once; `npm run test:watch` starts it in watch mode.

## Coding Style & Naming Conventions

Use TypeScript/TSX and follow the existing two-space indentation and semicolon style. Use PascalCase for component identifiers and camelCase for functions, variables, and hooks. Keep route UI in its route module; move reused behavior to shared components or `src/lib/`. Use the `@/` alias for `src/` imports and TanStack Router's typed `Link` for internal navigation. Follow existing Tailwind and shadcn/Radix patterns. No formatter is configured; ESLint is the available style check.

## Modularity & Maintainability

Keep modules cohesive and small, with clear ownership and typed interfaces. In the React frontend, use function components and hooks; separate reusable UI, stateful behavior, and data access rather than mixing them into large route components. Keep components focused, lift shared logic into hooks or `src/lib/`, and avoid duplicate implementations. Follow React's rules of hooks and prefer composition over complex component inheritance or implicit shared state. Keep routing and navigation within TanStack Router's typed APIs.

There is no backend in this repository today. If one is added, keep it in a distinct server-side area and follow that framework's conventions for routing, validation, business logic, persistence, and error handling. Keep transport handlers thin, validate inputs at system boundaries, and isolate persistence behind focused modules. Do not import server-only code into the browser bundle or share code across client/server boundaries without checking that it is safe in both environments.

## Testing Guidelines

Vitest, jsdom, and React Testing Library are configured for frontend unit and UI tests. Keep `*.test.ts` and `*.test.tsx` files under `src/` but outside `src/routes/`, so TanStack Router does not treat them as routes. Use accessible roles and labels to query UI, and `user-event` to simulate interactions. Shared test setup lives in `src/test/setup.ts`; Vitest configuration is in `vitest.config.ts`. Run `npm run test` once or `npm run test:watch` during development. jsdom requires Node.js 22.22.2 or newer in the 22.x line, or Node.js 24.15 or newer. No coverage threshold is configured.

The current test environment covers browser-side behavior only; this repository has no backend. If backend code is added, configure tests for its runtime and framework and cover server logic and API boundaries separately. Before submitting changes, run `npm run test`, `npm run lint`, and `npm run build`.

## Commit & Pull Request Guidelines

Git history currently contains only the initial commit, so no established commit-message convention can be inferred. Use a concise imperative subject that describes the change. Pull requests should summarize user-visible behavior and key implementation details, link a relevant issue or spec when available, and include screenshots for visual changes. Note the lint/build checks performed and any known gaps.

## Configuration Notes

Install dependencies with npm and commit `package-lock.json` when dependency changes are intentional. Keep secrets and local environment values out of source control; no environment-variable scheme is currently documented.
